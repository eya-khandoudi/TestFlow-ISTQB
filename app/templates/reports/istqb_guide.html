ISTQB Testing Methodologies in TestFlow

How this project applies and implements standardized software testing techniques throughout the SDLC & STLC.

1. Equivalence Partitioning (EP)

Goal: Divide input domain into partitions where all elements are expected to produce equivalent system behavior.

Application in TestFlow:
  • User Email Partitioning: Valid partition (e.g. test@domain.com) vs Invalid partitions (missing @, missing top-level domain, illegal characters).
  • Risk Rating: Valid partition integer [1, 5] vs Invalid partitions (< 1, > 5, non-numeric).
Associated Test Case: TC-EP-001, TC-EP-002
Automated Test: tests/istqb/test_equivalence_partitioning.py
2. Boundary Value Analysis (BVA)

Goal: Test edges of equivalence partitions, where the highest concentration of software defects typically resides.

Application in TestFlow:
  • Cart Item Quantity [1 .. 99]:
    • Min Boundary: Qty = 1 (Valid min)
    • Below Min: Qty = 0 (Invalid boundary → triggers BUG-001)
    • Max Boundary: Qty = 99 (Valid max)
    • Above Max: Qty = 100 (Invalid boundary → triggers BUG-002)
Associated Test Cases: TC-BVA-003, TC-BVA-004, TC-BVA-005, TC-BVA-006
Automated Test: tests/istqb/test_boundary_value_analysis.py
3. Decision Table Testing (DTT)

Goal: Validate business rules involving complex combinations of boolean conditions and resulting actions.

Application in TestFlow:
  • Discount Voucher Rules: Combines order threshold ($ > 100) and promo validity (SAVE20 vs ISTQB10).
  • Defect Triage SLA: Severity (Blocker/Critical vs Major) + Environment (Prod vs QA) + Core Flow → SLA Hours (4h, 8h, 24h, 48h).
  • IEEE 829 Release Gate Decision: Open Blockers == 0 AND Pass Rate ≥ 90% AND Critical Tests Pass → GO / NO-GO.
Associated Test Cases: TC-DT-007, TC-DT-008
Automated Test: tests/istqb/test_decision_table.py
4. State Transition Testing (STT)

Goal: Verify valid state transitions and guarantee that illegal transitions are strictly rejected by the system.

Application in TestFlow:
  • Defect Lifecycle State Machine:
    New → Assigned → Open → Fixed → Retest → Closed (or Reopened)
  • Transition Enforcement: TestFlow blocks illegal transitions like New → Closed or Open → Closed directly.
Implemented in: app.services.istqb_engine.validate_defect_transition
Automated Test: tests/istqb/test_state_transition.py
5. Risk-Based Testing (RBT)

Goal: Prioritize test execution and allocate testing effort based on the product risk level of failure.

Application in TestFlow:
  • Risk Priority Number: $RPN = Likelihood \times Impact$ ($1 \le L, I \le 5$, Score $1 \dots 25$).
  • Dynamic Sorting: Test Runs prioritize high-risk scenarios first to surface critical blockers early.
Associated Test Cases: TC-PAY-009 (Score = 15, High Risk), TC-PAY-010 (Score = 20, Critical)
Automated Test: tests/istqb/test_risk_based_testing.py
6. Error Guessing & Regression Testing

Goal: Experience-based identification of edge cases, and automated regression suites to guarantee stability after changes.

Application in TestFlow:
  • Error Guessing: SQL Injection payloads, XSS script injection, empty strings, rapid multi-click submissions.
  • Regression Suite: Tagged regression test cases executed automatically via pytest -m regression.
Associated Test Cases: TC-EG-011, TC-REG-012
Automated Test: tests/istqb/test_error_guessing.py, tests/regression/test_regression_suite.py
